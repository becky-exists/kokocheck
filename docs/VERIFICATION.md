# 検証の範囲

何を確かめていて 何を確かめていないかの一覧です。数字は `npm test` と `npm run build` の実行結果に合わせて更新します。

## 自動検証

| 項目 | 内容 |
| --- | --- |
| `npm run build` | フロントとサーバーの型検査 Viteビルド サーバーのコンパイル |
| `npm test` | 52テスト 失敗0 |
| `npm run security-check` | `npm audit`（high以上）の検出0 |
| `npm run release:source` | 収録ファイルの一覧化とローカル情報の検出（[RELEASE.md](RELEASE.md)） |

テストの対象:

- 実際のH.264/AAC MP4の取り込み・配信（Range 206）・FFmpegによるピン付きJPEG生成。入力形式は MP4/MOV に固定。
- レビュー権限と管理権限の分離。Host/Originの検証（IPv6のloopback表記を含む）。別レビューへのアクセス拒否。管理画面の自動ログインが公開URL設定で閉じること。再受付が管理者だけに限られること。
- 排他取得・リース期限・二重処理の防止・旧版への誤登録拒否・保存失敗時のロールバック。リース保持者による手放し。動画の長さを超える範囲の丸め。
- 指摘・返信の件数と長さの上限（排他の中での確認）。操作セッションの上限。起動時の掃除。
- MCP（stdio）での依頼取得・証拠画像・動画取得・修正版登録・手放し。ファイルパスの許可フォルダ制限。
- 自動runnerとサンプルadapterでの動画取得から修正版登録まで。`--agent claude` の経路の試験であり Claude本体を呼び出したテストではありません。`--approve` が端末なしで拒否されること。
- Codex通知: コマンドが文字列のまま渡ること・CLIの受付応答の照合・連打時の1回送信・再起動後に再送しないこと・失敗時も依頼が残ること。
- Claude通知: 受け口の認証・Origin拒否・別レビューの拒否・複数レビューを1つの受け口で扱うこと・設定の読み直し・通知文のURLに鍵が入らないこと・未送信の通知の再送／取り消しと 不明な通知は出さないこと・セットアップが既存設定を壊さないこと。

## 手動確認

次の画面操作は 実装時にブラウザーで確認しました（Chromium系 デスクトップ幅と390×844）。回帰テストは自動化していません。

- レビュー画面の再生・コメント・ピン・範囲指定・依頼送信・修正前後の比較・変更区間だけの再生。
- 演出アシストの選択と 再読込後の下書き復元。

## 未確認

- iPhone Safariなど実機のキーボード・タッチ・スワイプ。
- 実際のAIによる生成元の修正とレンダリングの品質。同梱の接続例（`agent-adapter.mjs`）は実AIでの編集品質を検証していません。
- Windows。Dockerはnative LinuxのarmのビルドとMP4取り込みを確認したのみで amd64は未確認。
- Claude Codeの開発用Channels機能は試験提供です。着信の既読確認はなく 実際の会話での動作は使用するバージョンに依存します。
- 長時間・大容量の負荷試験。公開インターネット向けの運用（rate limit・監査ログ・リンク失効など）は含みません。
- 通知設定画面（再送・取り消しのボタン）の見た目のブラウザー確認は 自動テストがAPIまでです。
